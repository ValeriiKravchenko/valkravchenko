# Прогоны git 2.53.0, 19.10.2026 (поток g18g2), LC_ALL=C, GIT_PAGER=cat, GIT_CONFIG_NOSYSTEM=1, HOME и XDG_CONFIG_HOME внутри каталога из mktemp -d,
#   git запускается как `git -c log.decorate=short -c init.defaultBranch=master`, под stdbuf -oL -eL: порядок строк stdout и stderr такой, как на терминале.
# Автор и коммиттер: Валера <valera@example.com>. Каждая команда сдвигает часы на минуту (GIT_AUTHOR_DATE/GIT_COMMITTER_DATE),
#   начиная с Mon Jun 1 10:00:00 2026 +0300, поэтому хэши воспроизводимы внутри файла и совпадают с хэшами appendix-g18g-git-runs.txt для исходной истории
#   (README — fc30a66, «О проекте» — da2dfdc, fix — 60eddbb, базовый — 535ca80), дальше зависят от порядка команд. Каждый блок начинается с исходной истории
#   раздела 8, как в П8.1 (файлы кончаются переводом строки: app.js, README.md, about.html), HEAD на master, рабочий каталог чист; после блока каталог удалён.
#   Каталог прогона в выводе заменён на /work.
# Служебные шаги: `edit <файл>` дописывает ` + правка` перед концом строки файла (так ✎ меняет файл в тренажёре), `mkfile <файл>` создаёт файл
#   с одной строкой «новый файл», `rm <файл>` удаляет файл. Это не команды git; вывода у них нет. Команды с `-q` — подготовка, их вывод образцом не служит.
#   Слова `{short:…}` и `{full:…}` в записи команды заменены настоящими 7 или 40 знаками id той ссылки, которая в скобках (так набрал бы игрок).
# Блоки П8.69–П8.81 закрывают формы, которых нет в section8-git-runs.txt (П8.4, П8.5, П8.10), detached-head-git-runs.txt (О6, О18, О20) и
#   appendix-g18g-git-runs.txt: `git reset` в трёх режимах на ветке и в отсоединённом HEAD (запись журнала, правки, `Unstaged changes after reset:`),
#   `reset --hard HEAD@{n}` на брошенный коммит, `git cherry-pick` (ссылки, правки в рабочем каталоге и в индексе, пустая копия, конфликт, удаление файла),
#   `git reflog -<n>` и `git log -g --oneline -<n>`.
# Формат: "$ команда", вывод (stdout+stderr), [exit код]. Пустая строка в конце вывода команды — это перевод строки в конце вывода git.
